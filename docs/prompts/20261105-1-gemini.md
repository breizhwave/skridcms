# Commit: Fix inline editing when editable elements are nested inside links

## The Bug
In Skrid's in-page editor, clicking an editable element that was nested *inside* an `<a>` tag (e.g. `<a href="..."><h3 data-skrid="1">Title</h3></a>`) would trigger browser navigation instead of activating the inline editor.

This occurred because `skrid/assets/bar.js` relied solely on `a.closest('[data-skrid]')` to suppress default link behavior during edit mode. While this correctly catches `<a>` tags inside editable blocks, it failed to detect editable blocks nested *inside* an `<a>` tag, causing Skrid to execute a redirect to the link destination.

## The Fix
Updated the click handler in `skrid/assets/bar.js` to comprehensively check the relationship between the click target, the anchor tag, and the `[data-skrid]` attribute.

**Previous check:**
```javascript
if (mode === 'edit' && a.closest('[data-skrid]')) { e.preventDefault(); return; }
```

**New check:**
```javascript
if (mode === 'edit' && (e.target.closest('[data-skrid]') || a.closest('[data-skrid]') || a.querySelector('[data-skrid]'))) {
  e.preventDefault();
  return;
}
```

## Why this works
- `e.target.closest('[data-skrid]')`: Successfully intercepts clicks directly on editable elements nested within links (e.g., headings or paragraphs inside a card link).
- `a.querySelector('[data-skrid]')`: Intercepts clicks on the padding or background of a card link that wraps editable elements, ensuring stable selection.
- `a.closest('[data-skrid]')`: Maintains the existing behavior for links nested inside an editable sentence.
- Normal navigation links (like in the site header or footer) remain functional, allowing seamless page browsing while in edit mode.
